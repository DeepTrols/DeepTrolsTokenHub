## 二、Provider 自动模型发现

**产品原理**：管理员输入厂商 API Key → 系统自动调用上游 /models API → 发现旗下所有模型 → 自动创建 Model + Channel + Instance + 定价。

### 2.1 修复 `discoverModels` — 多厂商 API 兼容

`internal/handler/console/providers.go`

| 厂商 | 认证方式 | 模型列表 API |
|------|----------|-------------|
| OpenAI | `Authorization: Bearer <key>` | `/v1/models` |
| DeepSeek | `Authorization: Bearer <key>` | `/v1/models` |
| Anthropic | `x-api-key: <key>` | `/v1/models` |
| Google Gemini | `?key=<key>` URL 参数 | `/v1beta/models` |
| Qwen/阿里 | `Authorization: Bearer <key>` | 自定义 base URL |

**改动**：
- 新增 `buildModelEndpoints()` — 根据 provider 类型构建正确的 URL 和 HTTP 头
- 新增 `parseGoogleModels()` — 解析 Google `{models: [{name: "models/..."}]}` 格式
- 新增 `parseOpenAIModels()` — 解析 OpenAI 兼容 `{data: [{id: "..."}]}` 格式
- 修复 `defaultBaseURLs` — 不再在 base URL 中包含版本路径，避免 `v1/v1/models` 双重拼接
- 扩展 `matchesProvider()` — 覆盖更多模型名称模式

### 2.2 Provider 凭证持久化

**问题**：模型发现失败时（API Key 无效或网络不通），整个请求返回 502 错误，凭证不保存。

**修复**：
- 模型发现改为 best-effort：成功则创建模型和通道，失败则创建 placeholder 凭证
- placeholder 凭证在 Provider 列表中可见，用户可编辑修正 API Key
- 返回 `warning` 字段提示模型发现失败原因

### 2.3 Provider 列表名称修复

- 创建实例时在 config JSON 中存储 `display_name` 字段
- 列表查询使用 `COALESCE(config->>'display_name', config->>'provider', ...)`
- 修复变量错误：`Name: providerName` → `Name: name`

### 2.4 前端 Provider 选项

`web/src/pages/Providers.tsx` — 新增 `Qwen / 通义千问` 到提供商下拉选项

## 四、Playground "Invalid API key" 修复

### 根因

`HandleGetAPIKeySecret` 每次调用都生成**新的随机 key** 并覆盖数据库中的 `key_hash`：

```
创建 key → plaintext dt-sk-aaaa, 存储 hash(aaaa)
获取 Secret → 生成新 key dt-sk-bbbb, 覆盖 hash(bbbb)!
Gateway 收到 dt-sk-aaaa → hash(aaaa) → 查不到 → Invalid API key
```

### 修复方案：加密存储

| 层 | 改动 |
|----|------|
| **新包** `internal/pkg/encrypt/encrypt.go` | AES-256-GCM 加密/解密 |
| **数据库** | `api_keys` 新增 `encrypted_key TEXT` 列 |
| **域模型** `internal/domain/apikey.go` | 新增 `EncryptedKey string` 字段 |
| **仓库** `internal/repository/apikey/postgres.go` | SELECT/INSERT/UPDATE 新增 encrypted_key |
| **处理器** `internal/handler/console/apikeys.go` | 创建时加密存储，获取时解密返回 |
| **Legacy 兼容** | 无 `encrypted_key` 的老 key 首次获取时自动重新生成并加密 |

### 验证

```
创建 key    → dt-sk-55a7****ebc8
获取 Secret → dt-sk-55a7****ebc8（相同！）
Gateway     → ✅ 认证通过
```
