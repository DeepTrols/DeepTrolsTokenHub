## 0. 实现方式

核心资金路径，按 TDD（RED→GREEN）：先写 `factory_test.go`（8 用例）RED，
再实现 `newGatewayForChannel` 工厂与 service 接线。

设计决策：

1. `newGatewayForChannel(cfg)` 按 `payment_channel` **精确匹配**选择实现：
   - `epay` ⇒ `EpayGateway`（携带 PayAddress / EpayID / EpayKey，
     NotifyURL = `<callback_base>/api/payment/notify/epay`）；
   - `alipay` / `wechatpay` ⇒ `ErrChannelNotReady`（provider adapter
     未落地前 fail closed；具体实现留给 TH-P1-AL-* / TH-P1-WX-*）；
   - 其他任意值（含 `"Epay"`、`"epay "`）⇒ `ErrInvalidChannel`。
   仅**空设置**回落到默认的 epay（`normalizeChannel`），配置笔误绝不
   静默把付费流量路由到错误网关。
2. 工厂失败发生在 `orders.Create` 之前 —— 失败渠道**不留**
   `payment_orders` 行。
3. `CreateOrder` / `CreateSubscriptionOrder` 的订单行与响应 `Channel`
   改取 `normalizeChannel(cfg.Channel)`（原先硬编码 `"epay"`）；
   NotifyURL 按渠道拼接（`/api/payment/notify/<channel>`），为
   TH-P1-04 回调路由准备按订单渠道解析的基础。
4. `CreateSubscriptionOrder` 内 epay 专属凭据前置检查下沉至
   `EpayGateway.client()`（返回 `ErrNotConfigured`），service 层不再
   携带 epay 专属逻辑。
5. `Info()` 仅当生效渠道为 epay、支付启用且凭据齐备时才暴露
   `pay_methods`；未就绪/未知渠道不广告可支付方式。

### 渠道值文档（Documentation Requirements）

- 有效值：`epay` / `alipay` / `wechatpay`（常量 `ChannelEpay` /
  `ChannelAlipay` / `ChannelWeChatPay`），持久化于
  `payment_orders.channel`，选择来源为设置项 `payment_channel`。
- **临时 epay 回落**：只有空的 `payment_channel` 设置回落 epay；
  `alipay` / `wechatpay` 在 provider adapter 任务（TH-P1-AL-*、
  TH-P1-WX-*）落地前为 not-ready，创建订单即以配置错误失败关闭，
  不产生订单、不收款。

### 可观测性（Observability Requirements）

`log.Printf` 仅记录渠道值与错误类（`payment: channel %q rejected: %v`、
`payment: order %s created via channel %q`）；任何路径都不打印
PayAddress / EpayID / EpayKey 等凭据。
