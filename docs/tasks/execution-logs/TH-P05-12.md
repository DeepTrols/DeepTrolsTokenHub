## 2. Implementation 摘要

按任务要求系统盘点全部会产生 Provider Cost 的网关入口，建立
`Endpoint → Pricing Unit → Maximum Exposure → Reserve Strategy` 矩阵，
并把 Batch 1 审计缺口 C-1 / C-2 / C-3 全部收口。**禁止的第四种策略
（"无法计算所以静默使用 minHoldAmount"）已从代码中消除。**

- **C-1（空估算器）**
  - `/v1/completions`：`estimateCompletionsUsage` 从返回空
    `NormalizedUsage{}` 改为真实估算 —— `completionsPromptTokens`
    支持 string / []string / token-id 数组（1 id = 1 token），输出取
    声明的 `max_tokens`/`max_completion_tokens`（上限 131072）；
    `validateCompletionsRequest` 强制 prompt 必填（缺失 → 400，
    不再可能走到"空 prompt 估算"）。
  - `/v1/responses`：`estimateResponsesUsageStrict` 处理多态
    `input`（string / item 列表；item 为 string、content 字符串、
    多模态 content parts、`call.arguments`、未知形状按 JSON 编码计），
    `instructions` 计入，输出取 `max_output_tokens`（上限 131072）。
    直转分支在预留前强制走严格估算；不可定价内容 → 422
    `pricing_incomplete`。via-chat 分支维持 `computeMaxChargeHold`
    （转换后为纯文本，估算基于存活文本正确）。
- **C-2（定价错误静默 minHold）**
  - 新增 `computeForwardedHold`（reserve.go）：定价出错或出现
    MissingPricing → 422 `pricing_incomplete`，**不预留、不调用
    Provider**；定价完整时取 `priceResult.ListCost`（minHold 仅作
    下限安全网）。`hold_calc` 日志记录 endpoint + 金额桶，不含请求体。
  - 四个转发管线（`handleForwardedEndpointExecution`、
    `handleForwardedRawExecution`、`handleForwardedMultipartExecution`、
    video.go）的 `(using minimum hold)` 静默块全部替换为该函数。
- **C-3（chat 多模态 parts 未计入）**
  - `estimateUsageFromBody` 增加 `content []any` 分支：
    `estimateContentPartsTokens` 按 `chatContentPartTokens` 分类 ——
    text / input_text / output_text 走文本估算；image_url / input_image
    计 `imagePartHoldTokens=3072`（覆盖 OpenAI high-detail ≤~2805 的
    最坏值）；input_audio 计 `audioPartHoldTokens=4096`（1MB body 上限
    约束）；无类型但含 text 按文本；**其余（file 引用、未知类型）为
    不可定价**。
  - `computeMaxChargeHold` 新增门禁：`unpriceableChatPartTypes` 非空 →
    422（Strategy C），绝不把不可定价内容当免费文本跳过。
- **各端点真实计价单元修正**
  - STT：文件字节 → 秒的换算从 16000 B/s（128kbps 假设）改为最坏编解码
    下限 `sttBytesPerSecondFloor=750`（~6kbps opus），**预留与
    无-usage 结算用同一基准**（二者永不分离，否则重开 B5 洞）；
    不足 1 秒按 1 秒下限。
  - embeddings：`input` 为 token-id 数组（`[[1,2,3]]`）时按 1 id = 1
    token 精确计数，不再静默落到最小值。
  - images/edits：`n` 为表单字符串，新增 `validateImagesEditsCount`
    校验 1..10（非法 → 400）；估算器对超界/异常值回落默认 1。
    images/generations 既有 `validateImagesRequest` 已校验 1..10。
  - videos/generations：`videoCountFromBody` 既有 1..10 校验不变，
    预留改走 `computeForwardedHold`（VideoUnits=n）。

未改动（Out of Scope）：定价模型、牌价、Provider 计费契约 —— 各端点
计价单元均取自现有 Pricing Engine（`pricer.go` tokenDimensions /
image / audio / tts / video 维度）。

  最坏编解码计秒，高码率音频在上游不返回 usage 时会被高估计费；
  预留与结算同基准，永不低估（B5 洞不重开）。改进方向（延迟项）：
  上游 duration 探测（ffprobe / 容器头），属未来运维/功能任务，
  不在本批范围。
- **Observation O-2（设计取舍）**：image 3072 / audio 4096 为基于
  body 上限推导的安全津贴，非 Provider 真实分词；表现为轻度过度预留，
  结算以上游真实 usage 为准。
- **Deferred（批级）**：C-4 备份加密仍为 Backlog Gap / 运维要求，
  本批不做（无 KMS/云备份/密钥管理架构引入）。
