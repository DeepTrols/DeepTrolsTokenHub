## 2. Implementation 摘要

把"结算无法按实际成本扣款（final > reserve 且钱包无额外可用余额）"
从各端点各自为政的静默兜底，收口为**单一分类器 + 证据链 + 对账可见**，
并显式禁止任何自动补扣路径。**禁止项（用对账自动改钱包来解决结算
失败）未发生：对账对钱只读，只产出复核差异。**

- **新增 `settle_fallback.go`（网关包）**
  - `classifySettleFailure(err) settleFailureClass` 三类判定：
    `wallet.ErrInsufficientBalance` → 提交预留 + `undercharged`；
    `wallet.ErrTxNotReserved` → 重放，**零钱包动作、零标记**；
    其他错误 → 提交预留 + `settle_error`，仅当
    `finalCost > reservedHold` 时升级为 `undercharged`。
  - `settleOrFallback(...)`：统一 9 个结算点。settle 成功原样返回；
    失败按分类提交预留金额；提交兜底再遇 `ErrTxNotReserved`
    （并发完结）返回零扣款，账本不双扣。
  - 观测：进程内计数器按 `endpoint|model` 记少收兜底次数，
    `UnderchargeFallbackCounts()` 导出快照（仓库暂无指标库，
    TH-P05-04 接线 Prometheus）；日志仅含 request id，不含请求体。
- **钱包仓库新增幂等哨兵 `wallet.ErrTxNotReserved`**
  - `postgres.go` 的 Commit / Settle / Release 状态检查统一
    `%w` 包装该哨兵；调用方据此识别"事务已不在 reserve 态"的重放，
    不再重试/改钱/误标少收。
- **证据码统一（`applySettleEvidence`）**
  - `usage_logs.error_code` ∈ {`undercharged`, `settle_error`,
    `pricing_incomplete`}；`undercharged` 附
    `actual / charged / shortfall` 金额消息。`pricing_incomplete`
    保持优先（定价不完整强制 final=hold，与 undercharged 可证互斥）。
- **9 个结算点全部切换**：chat 非流式、chat 流式（detached
  commitCtx）、chat usage 补结算、三条转发管线（multipart / raw /
  forwarded）、video、`/v1/messages`（Claude relay）、`/v1/responses`
  （via-chat）。后两者此前**从不记录 settle 错误**，观测缺口一并关闭；
  chat.go 原 `_ =` 吞掉提交错误、兜底时 `walletCharged=finalCost`
  的两处失真同时修正。
- **对账 L4 通道（reconciler.go）**
  - `findUndercharged`：按时间窗扫 `usage_logs.error_code =
    'undercharged'`（LIMIT 100/轮），产出
    `reconciliation_diffs`：`diff_type=undercharge_review`、
    `severity=critical`、detail 含 `list_cost` 与 `wallet_charged`。
  - 对账对钱严格只读：不出现任何 `Spend / TopUp / Adjust / Reserve /
    Settle` 或钱包写 SQL；报告新增 `L4.undercharged` 计数。
