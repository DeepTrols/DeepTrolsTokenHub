## 2. Implementation 摘要

目标：chat 类文本推理路径在上游调用前按「最大可能费用」预留，替代
最小/粗略预留，消除 B5 少收洞（静默 `minHoldAmount` 兜底）。

新增 `internal/handler/gateway/reserve.go`（计算器 + 统一预留入口）：

- `maxHoldOutputTokens(body)`：读取 `max_completion_tokens`（优先）/
  `max_tokens`；正值取声明值并以 `maxChargeOutputCap=131072` 封顶；
  缺失/0/负数/非数值 → 文档化兜底上限 `fallbackOutputTokens=256`
  （沿用 `estimatedOutputTokens`）。返回模式 `declared_max` /
  `fallback_cap` 供测试与观测使用。
- `holdUsageFromChatBody(body)`：提示词估算沿用
  `estimateUsageFromBody`（未改动该函数，chat.go:67 API Key 边界检查
  行为保持不变），输出替换为上述上限；`TotalTokens` 重算。
- `computeMaxChargeHold(...)`：按最大用量走 `priceWithAdjustments`
  （decimal，含分组/阶梯倍率）。**fail-closed**：pricer 报错 →
  422 `pricing_incomplete`，不产生预留流水、不调用上游；MissingPricing →
  复用 `rejectIncompletePricing` 422。成功后预留 = ListCost，且不得低于
  `minHoldAmount`（AC-03 下限）。
- `reserveAmountBucket(...)`：低基数金额分桶观测标签。
- 观测日志：`gateway: hold_calc mode=… pricing_complete=true
  reserve_bucket=…`，不含请求体文本。

接入点（全部 4 条 chat 形态路径，替换各自复制的旧预留块）：

- `chat.go` `HandleNonStreamingChat`（非流式）
- `chat.go` `handleStreaming`（流式，保留 `estimatedUsage` 仅供无
  usage 时的结算回退，语义不变）
- `responses_via_chat.go` `handleResponsesViaChatNonStream`（流式走
  `handleStreaming`，同链覆盖）
- `claude_relay.go` `HandleClaudeMessages` 非流式（对转换后的 chat body
  计算，`ClaudeToOpenAIRequest` 已携带 `max_tokens`；流式走
  `handleStreaming`）

附带修复（Category A，当前任务路径上的数据丢失缺陷，详见 §7）：

- `responses_via_chat.go` `responsesBodyToChatBody`：字符串 `input`
  归一化项补 `"type":"message"`，否则
  `ResponsesRequestToOpenAIChatRequest` 会静默丢弃用户输入（上游收不到
  提示词，预留也拿不到提示词估算）。
- `chat_test.go` `TestHandleNonStreamingChat_SettleUnderfunded_MarksEvidence`：
  用量数据 100k→1M output tokens，使欠费场景在新预留下限
  （≥0.0001）下仍真实成立（断言语图不变）。

未改动（保持既有行为）：`endpoints.go`（embeddings/images/STT/TTS）、
`video.go`、直连 `responses.go` / `completions.go` 估算器 —— 超出本任务
