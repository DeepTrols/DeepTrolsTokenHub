- **`scripts/restore_drill.sh`（演练工具）**
  - 目标防护（AC-04）：生产形态库名（deeptrols / prod / production /
    live / main）一律拒绝；目标名必须含隔离标记
    （drill / test / staging / restore）；不安全字符拒绝。
  - 流程：目标防护 → DROP+CREATE 隔离目标库 → `pg_restore
    --no-owner --no-privileges --exit-on-error`（计时）→ 验证 → 报告。
  - 验证项：
    - **迁移版本（Batch 1 C-5 收口）**：本项目不维护
      `schema_migrations` 版本表（迁移按文件名顺序裸 SQL 应用，见
      `internal/repository/testutil/schema.go`），故验证 = 最新迁移
      标记对象存在性（000034 索引 / 000035 列 / 000036 表）+
      源/目标 schema 对象集合与列数指纹完全一致。
    - Manifest 7 表行数逐一相等（AC-02）。
    - 钱包不变量（AC-03）：W1 `frozen == 未完结 reserve 之和`；
      W2 `balance == 账本净额`；提供源库时违例集合必须与源库完全
      一致（恢复不得引入新违例）。
    - 内容级一致性：7 表逐行 md5 校验和、账本净额、分状态支付
      金额，源/目标相等（不止行数）。
  - 安全：URL 只进 libpq 环境变量（不进 argv）；输出统一 redact。
  - 退出码：0 通过；1 恢复/验证失败；2 参数/防护拒绝；3 环境缺失。
- **`scripts/seed_drill_fixture.sh`（演练数据播种，配套工具）**
  - 在隔离库构造"真实的钱与证据"：3 用户 / 3 钱包 / 3 API Key；
    完整钱包生命周期（topup → reserve → settle 低估退款 / settle
    超额补扣 / commit / release → 未完结 reserve 挂账）、
    subscription 消费、钱包间 transfer；payment_orders 全 4 状态
    （paid 订单与 topup 的 `idempotency_key=order_no` 契约对齐）；
    usage_logs 三种 `usage_source` 显式标记 + charge_lines +
    provider_evidence（含成功/失败两态）。
  - 播种后自校验 W1/W2 违例必须为 0，否则拒绝继续。
  - 目的：使演练在非空账本上真正检验不变量与内容一致性。
- **`docs/DEPLOYMENT.md` §5.3**：新增恢复演练操作步骤、验证项说明、
  失败处理表（按退出码处置）、"生产恢复必须先经演练"约束。

未改动（Out of Scope）：生产恢复流程、schema 设计、备份工具
