## 2. Implementation 摘要

缺陷（任务 Current State 复核属实）：`payment_orders` 表（migration
000022，`pay_url TEXT` 可空）与 `paymentorder.Order` 结构体、下单响应
`CreateOrderResponse` 均有 pay_url，服务层下单时也设置了
`o.PayURL = &res.PayURL`（service.go:199/256），但
`PostgresRepository.Create` 的 INSERT **遗漏该列** → 待支付订单刷新后
支付链接丢失、不可继续操作。

修复（仅用既有 schema/DTO，无迁移、无新列、无新存储）：

- `internal/repository/paymentorder/postgres.go` `Create`：INSERT 列与
  占位符补 `pay_url`（$11，传 `o.PayURL *string`，NULL 语义天然兼容）。
- `internal/handler/console/payment.go`：`paymentOrderDTO` 增加
  `pay_url,omitempty`；`toOrderDTO` 仅当
  `Status == StatusPending && PayURL != nil` 时填充 —— 即
  **仅 pending、仅属主/管理端**（用户列表 `HandleListMyPaymentOrders`
  与管理端列表 `HandleListAllPaymentOrders` 共用该映射）；
  paid/closed/refunded 与历史 NULL 行一律缺省该字段。
- 观测约束：完整 pay_url 不落日志/指标 —— 支付服务包
  （`internal/service/payment/*`）无任何日志语句（grep 证据见 §4），
  handler 侧日志仅记录错误/操作结果，未打印订单字段。

文档：`docs/PROJECT_STATUS.md` §114（修复内容 + pay_url 响应可见性规则）。

未改动（Out of Scope 明示）：epay 适配器、支付状态轮询、前端 UI。
