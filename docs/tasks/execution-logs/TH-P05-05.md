全部静默规则：`sum by (worker)` 全集群聚合（HA 对端 `skipped` 是健康租约
选举，永不告警，Test E 固化）；只使用固定白名单，禁止 `worker=~".*"`
（`TestRules_WorkerSilenceNeverRegexAll` 固化，且校验 5 个租约 worker
全部有沉默覆盖）；双段式 `increase(...)==0 or absent(...)` 分别覆盖
“存活但停摆”与“进程死亡/从未导出”。

## 4. 新增最小指标（任务范围内，同一 registry）

1. `reconciliation_critical_diffs_total`（Counter，无标签）：仅在
   `severity="critical"` 的差异行**成功持久化**后递增（`createDiff` /
   `createBillingDiff` 两个咽喉点）；warning 类差异（TH-P05-08 幂等重放
   缺计费行）结构性地不计数 ⇒ critical 告警零噪声。对账保持 detect-only：
   计数本身不触发任何 Spend/Adjust/TopUp/借记/贷记。
2. `app_dependency_up{dependency}`（GaugeVec，`dependency` ∈ {database,
   redis, other} 白名单钳制）：由 `StartDependencyWatchdog`（15s 间隔、
   2s 超时）在 **API 与 worker 两个进程**驱动，探针为 `Pool.Ping` /
   `Redis.Ping`；未配置 Redis 时不注册该探针、序列不存在、Redis 告警永不
   触发。`safely()` 包裹：watchdog 故障只影响 gauge。

没有日志 grep 探针、没有第二个 registry、没有完整数据库 exporter、
没有告警平台/传呼集成。
