## 1. 实现摘要

仓库此前没有任何 metrics 库；本任务引入
`github.com/prometheus/client_golang v1.20.5`（新增依赖仅此一个直接项，
其余为传递依赖）并建立最小低基数基线：

1. `internal/pkg/metrics`：独立 `prometheus.Registry`（无 Go runtime /
   第三方采集器）；13 个受审家族；白名单消毒器 `SanitizeEndpoint` /
   `SanitizeReasonClass` 在所有 setter 入口结构性强制低基数；`safely()`
   recover 守卫保证指标故障永远不影响业务请求。
2. `internal/handler/middleware/gateway_metrics.go`：chi 中间件，
   在 `/v1` 路由链最前（`cmd/api/main.go`），handler 之后用
   `RoutePattern()` 计数请求/成功/错误/耗时（鉴权与限流拒绝也被计入）。
3. `internal/service/billing/charger.go`：reserve/settle/release 成功与失败
   计数（资金路径单点接入，避免装饰器/接口改造）。
4. `internal/handler/gateway/settle_fallback.go`：undercharge fallback 计数
   （进程本地 `UnderchargeFallbackCounts()` 保留，TH-P05-03 测试依赖）。
5. `internal/handler/gateway/reserve.go`：5 个 fail-closed 分支统一
   `pricing_incomplete` + `provider_blocked(pricing_incomplete)` 计数。
6. `chat.go` / `claude_relay.go` / `responses_via_chat.go` / `video.go` /
   `endpoints.go`：所有 pre-executor 拒绝分支（wallet_missing /
   insufficient_balance / reserve_failed）计 `provider_blocked_before_call`。
7. `internal/app/app.go`：`/metrics` 挂载（Prometheus 文本格式）。

端点标签归一化：`endpointAliases{"chat": "chat/completions"}` 使计费调用点
短形式与路由命名空间合并为同一标签值（同一端点只有一个序列）。

**provider_blocked_before_call_total 为文档化的 surrogate**：真实“被阻止的
provider 调用”无法在 executor 内计数，但不变量 W6（TH-P05-03 已证：每笔
provider 调用前必有成功 reserve）使 executor 之前的每次拒绝恰好等价于一次
被阻止的调用。详见 `docs/OBSERVABILITY_METRICS.md` §1。

  钳制为 `other`，业务响应不被埋点改变）— PASS。
- **Regression**: `TestHandler_Scrapeable`（200 + `text/plain` + 12 个计数
  家族齐全 + 无敏感子串）、`TestRegisterRoutes_MetricsEndpoint`（/metrics
  可抓取，且 /health、/readyz 行为不变）— PASS。
- **Failure Injection**: `TestSafely_InstrumentationFailureNeverPropagates`
  （panic 被吞掉，不外泄）；所有 setter 均经 `safely()`；中间件在 handler
  之后计数，埋点故障无法改变已写出的响应 — PASS。
