## 2. Implementation 摘要

目标：把备份从「文档里的一行 `pg_dump`」升级为**可执行、可验证的基线**：
备份命令 + 留存位置 + 加密预期 + 资金/证据表行数 manifest。

新增 `scripts/backup_db.sh`（可执行，bash 3.2 兼容，`bash -n` 通过）：

1. `pg_dump -Fc` 全量转储 → `<OUT>/deeptrols_<UTC时间戳>.dump`
   （与旧文档命令同语义，仅增强安全与校验）。
2. 行数 manifest → 同名 `.manifest`，固定 7 张资金/证据表：
   `users / wallets / wallet_transactions / payment_orders / usage_logs /
   charge_lines / provider_evidence`；一条 UNION ALL SQL，全部成功才
   **原子落盘**（tmp+mv）——任何失败 → 非零退出且无 manifest（杜绝假
   manifest）。
3. 报告（observability 要求）：`backup: OK duration=…s dump_bytes=…
   dump_path=… manifest_path=…`。

安全约束（AC-03 设计）：

- DATABASE_URL 解析为 libpq 环境变量（PGHOST/PGPORT/PGUSER/PGPASSWORD/
  PGDATABASE），URL 与密码**不出现在进程命令行**；支持 `?查询串` 剥离与
  `%XX` 凭据解码。
- 所有子进程输出统一经 redact 过滤后才打印（密码 → `[REDACTED]`）。
- 退出码：0 成功；1 备份/manifest 失败；2 参数错误；3 缺 `pg_dump`/`psql`。

  cron 示例）、5.2 存储与加密预期（异地留存、离开本机前必须加密、
  manifest 与 dump 成对）、5.3 恢复（`pg_restore` 指引，演练明确指向
  TH-P05-07，不在本任务执行）。
- `docs/PROJECT_STATUS.md` §113 记录备份基线。
