## 0. 实现方式

核心资金路径，按 TDD（RED→GREEN）：先写 `query_test.go`（10 用例）令其编译失败
（`Gateway` 接口尚无 `QueryOrder`），再实现契约。

设计决策：

1. **封闭枚举** `QueryOrderState`：`paid` / `not_paid` / `closed` / `unknown`，
   精确、大小写敏感匹配。理由：含糊的状态名会造成错误结算（false
   settlement），未识别的 provider 状态绝不能映射为 paid。
2. `NormalizeQueryState(raw)`：非封闭枚举成员一律映射为 `unknown`（永不
   paid），不暗示任何本地结算迁移意图。
3. `QueryOrderResult.Validate()` 防错误结算不变量：
   - `paid` ⇒ 必须携带 GatewayTradeNo + 正数 Amount + 非零 PaidAt，且 Retryable=false；
   - `Retryable=true` ⇒ State 必须为 unknown 且零 paid 字段（如 provider 超时）；
   - `not_paid` / `closed` / `unknown` ⇒ 不得携带任何 paid 字段。
4. `Gateway` 接口新增 `QueryOrder(ctx, orderNo)`。bundled epay 库
   （Calcium-Ion/go-epay v0.0.4，已在 GOMODCACHE 源码核实）只暴露
   Purchase/Verify，无查单路径；`EpayGateway.QueryOrder` 因此返回
   `ErrQueryUnsupported` 哨兵，把真实查单留给补偿 worker 任务
   （TH-P1-CW-*），契约先显式占位而不是静默成功。
