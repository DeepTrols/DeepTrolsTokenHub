# DeepTrols MaaS 改造方案（目标模式）

> 文档性质：目标态设计文档。描述改造完成后系统"应该长什么样、怎么工作"，作为实现与验收的依据。
> 版本：v1.0　日期：2026-08-29　范围：A 站点与品牌 / B 计费与支付 / C 渠道模型检测与自动同步

---

## 1. 背景与目标

DeepTrols 的最终定位是 MaaS（Model-as-a-Service）一站式接入基础设施：开发者/企业在一个平台完成
注册 → 取 Key → 调用 → 计量 → 支付 → 对账 → 审计的完整闭环。

本方案对齐 three 条工作线：

| 工作线 | 目标态能力 | 关键决策（已定） |
|---|---|---|
| A 站点与品牌 | 平台品牌（名称/Logo/公告/页脚/协议/导航）全部后台可配，前端动态消费 | 全局品牌；公司域名走部署配置 |
| B 计费与支付 | 支付宝/微信真实充值，订单、回调、幂等入账、管理补单闭环 | 易支付先行；官方支付宝/微信适配器预留 |
| C 渠道模型同步 | 渠道级"测试 + 发现上游模型 + 绑定"，支持预览确认或自动创建 | 默认预览确认，可勾选自动创建 |

公共底座：`system_settings`（key/value 配置表）同时承载 A 的品牌配置与 B 的支付配置。

## 3. B 计费与支付

### 3.1 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 通道 | 易支付先行 | 与 new-api 同款（`Calcium-Ion/go-epay`），一个通道同时覆盖支付宝+微信，最快跑通 |
| 微信官方 | 仅 Native 扫码（PC 端） | 目标用户是开发者/企业，主要在电脑网页操作；手机 H5/JSAPI 后续按需扩展 |
| 官方适配器 | 预留扩展位，不阻塞 M0 | 企业商户资质到位后再切 |
| 金额 | 沿用 decimal，订单金额 CNY | 与钱包、账单体系一致 |

### 3.2 支付网关抽象

```go
// internal/service/payment/gateway.go（目标态）
type Gateway interface {
    Name() string                       // "epay" / "alipay" / "wechat"
    CreateOrder(ctx context.Context, req CreateOrderRequest) (*CreateOrderResult, error)
    VerifyNotify(ctx context.Context, r *http.Request) (*NotifyResult, error)
}

type CreateOrderRequest struct {
    OrderNo    string          // 平台单号 DTP20260829xxxx
    Amount     decimal.Decimal // CNY
    PayMethod  string          // alipay / wxpay
    Subject    string
    NotifyURL  string
    ReturnURL  string
}

type CreateOrderResult struct {
    PayURL string // 易支付跳转/二维码地址；官方 Native 为 code_url
}

type NotifyResult struct {
    OrderNo        string          // 平台单号（out_trade_no）
    GatewayTradeNo string          // 上游交易号（trade_no）
    Amount         decimal.Decimal // 回调金额（必须与订单比对）
    PayMethod      string
    Success        bool
}
```

### 3.3 数据模型（迁移 000021 追加）

```sql
CREATE TABLE payment_orders (
    id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    order_no         VARCHAR(64) NOT NULL UNIQUE,
    user_id          UUID NOT NULL REFERENCES users(id),
    amount           DECIMAL(18,6) NOT NULL,
    currency         VARCHAR(8) NOT NULL DEFAULT 'CNY',
    channel          VARCHAR(32) NOT NULL,            -- epay / alipay / wechat
    pay_method       VARCHAR(32) NOT NULL,            -- alipay / wxpay
    status           VARCHAR(32) NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending','paid','closed','refunded')),
    gateway_trade_no VARCHAR(128),
    pay_url          TEXT,
    notify_raw       JSONB,                           -- 回调原文留证
    paid_at          TIMESTAMPTZ,
    expires_at       TIMESTAMPTZ NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_payment_orders_user ON payment_orders(user_id, created_at DESC);
CREATE INDEX idx_payment_orders_status ON payment_orders(status, expires_at);
```

入账不写订单表：复用 `wallet_transactions`，回调成功写入 `tx_type='topup'` 流水，
**`idempotency_key = order_no`**（该列已有唯一约束，天然防重复入账）。

### 3.4 易支付适配器（M0 实现）

对接 `github.com/Calcium-Ion/go-epay`（new-api 同款），配置：
`pay_address`、`epay_id`（PID）、`epay_key`（商户密钥）、`callback_base_url`。

**下单**（`client.Purchase`）：

| 参数 | 值 |
|---|---|
| `Type` | `alipay` / `wxpay` |
| `ServiceTradeNo` | 平台 order_no |
| `Money` | 金额（CNY，两位小数） |
| `Device` | `epay.PC` |
| `NotifyUrl` | `{callback_base_url}/api/payment/notify/epay` |
| `ReturnUrl` | 前端账单/充值结果页 |

返回 `(uri, params)`：前端用 `uri` 展示二维码/跳转。

**回调**（`POST`/`GET /api/payment/notify/epay`，无鉴权）：

1. 解析表单/Query 参数；
2. `client.Verify(params)` 验签（MD5），失败返回 `fail`；
3. 仅处理 `TradeStatus == TRADE_SUCCESS`；
4. 查订单：存在、`pending`、金额一致（回调 money == 订单 amount）、未过期；
5. 数据库行锁 + 事务内 `pending → paid` CAS（防并发回调，多实例安全）；
6. 事务：钱包入账 + `wallet_transactions('topup', idempotency_key=order_no)` + 更新订单；
7. 返回 `success`；任何错误返回 `fail`（易支付会重试）。

### 3.5 官方适配器扩展位（M1，预留）

- **微信 Native**：`POST /v3/pay/transactions/native` 下单拿 `code_url`；回调用 APIv3 密钥
  HMAC-SHA256 验签 + 平台证书/公钥验签；返回报文需应答 `{"code":"SUCCESS"}`；
- **支付宝**：`alipay.trade.precreate`（当面付扫码）或 `alipay.trade.page.pay`（电脑网站）；
  回调 RSA2 验签；返回 `success`；
- 两者复用同一 `Gateway` 接口与订单表，仅新增 adapter + 管理端配置项。

### 3.6 接口清单

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/console/payment/methods` | 登录 | 可用通道（支付宝/微信）、最小/最大金额、预设档位 |
| `POST /api/console/payment/order` | 登录 | `{amount, pay_method}` → 创建订单，返回 pay_url |
| `GET /api/console/payment/orders` | 登录 | 我的充值订单列表（含状态） |
| `POST /api/payment/notify/{channel}` | 公开 | 支付回调（验签） |
| `GET /api/payment/notify/{channel}` | 公开 | 兼容 GET 回调 |
| `GET /api/admin/payment/orders` | admin | 全量订单查询（按单号/用户/状态） |
| `POST /api/admin/payment/orders/{id}/complete` | admin | 手工补单（回调丢失兜底，走审计） |

### 3.7 支付时序（目标态）

```
用户选择 支付宝/微信 + 金额
 → POST /api/console/payment/order（创建 pending 订单，调易支付下单，返回 pay_url）
 → 前端展示二维码/跳转
 → 用户扫码支付
 → 易支付回调 POST /api/payment/notify/epay
     → MD5 验签 → 金额/订单比对 → 行锁 CAS(pending→paid)
     → 事务：钱包 + topup 流水(idempotency_key=order_no) + 订单更新
 → 前端轮询订单状态 → 充值成功页
```

### 3.8 安全与幂等（对照 5 不变量）

1. 验签失败直接 `fail`，不返回成功；
2. 金额服务端二次比对，不信任回调参数；
3. `payment_orders.status` 状态机 + `wallet_transactions.idempotency_key` 唯一约束双保险；
4. 订单 30 分钟过期，过期拒绝入账；
5. `notify_raw` 留存回调原文（证据面延伸）；
6. 管理补单必须走审计日志；
7. `FakePayment=true` 保留 mock 充值（开发），`false` 且未配置通道时下单返回 403。

### 3.9 配置项（system_settings）

`payment_enabled`、`payment_compliance_confirmed`（合规确认弹窗）、`pay_address`、`epay_id`、
`epay_key`、`min_topup`、`max_topup`、`amount_options`（预设档位，如 10/50/100/500）、
`callback_base_url`。官方通道配置项（预留）：`alipay_app_id/private_key/alipay_public_key`、
`wechat_mch_id/api_v3_key/cert_serial_no`。

## 4. C 渠道模型检测与自动同步

### 4.1 目标行为

- 渠道管理页支持"测试"：选一个模型，用该渠道实例真实发一次请求，返回状态/延迟/错误；
- 渠道管理页支持"同步上游模型"：调用渠道实例上游 `/v1/models` 发现模型；
- 同步默认**预览确认**（列出"新发现/已绑定/已停用"，管理员勾选后应用）；
- 可勾选"自动创建"：发现的新模型自动建平台模型（定价默认 0，管理员后补）；
- 同步/测试记录进审计日志，可挂 `async_jobs` 异步执行。

### 4.2 数据模型（迁移 000022）

```sql
CREATE TABLE channel_models (
    channel_id      UUID NOT NULL REFERENCES channels(id) ON DELETE CASCADE,
    model_id        UUID NOT NULL REFERENCES models(id) ON DELETE CASCADE,
    upstream_model  VARCHAR(255) NOT NULL,   -- 上游模型名
    mapping         VARCHAR(255),            -- 可选：平台名 → 上游名别名
    enabled         BOOLEAN NOT NULL DEFAULT true,
    discovered_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (channel_id, model_id)
);
```

兼容策略：`channels.model_id`（单模型）保留，路由优先走 `channel_models`，空则回退单模型；
同步只做"新增/停用"（`enabled=false`），不做物理删除。

### 4.3 接口设计

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /api/admin/channels/{id}/test` | admin | `{model, endpoint_type}` → 真实请求测试，返回状态/延迟 |
| `GET /api/admin/channels/{id}/models/preview` | admin | 上游发现结果：新发现/已绑定/已停用 |
| `POST /api/admin/channels/{id}/models/sync` | admin | `{model_ids, auto_create}` → 应用绑定；`auto_create=true` 自动建模型（定价 0） |
| `GET /api/admin/channels/{id}/models` | admin | 渠道绑定模型列表 / 启停 |

### 4.4 复用与改造

- 把 [providers.go](E:\workspace\TokenHub\DeepTrolsTokenHub\internal\handler\console\providers.go)
  的 `discoverModels` / `parseOpenAIModels` / `parseGoogleModels` 抽到 `internal/provider` 独立函数，
  入参从 provider 改为 `(baseURL, apiKey)`，供 provider 与 channel 两处调用；
- 渠道测试复用网关执行链的最小路径（直连 + 超时），不产生计费记录（`test_mode` 标记）；
- 同步任务可走 `async_jobs`（000020 已有表），长任务异步 + 进度查询；
- 新建模型默认 `status='draft'` 或定价 0，避免不可解释账单。

   - 易支付 `uri` 为跳转/二维码页：优先内嵌二维码（若 params 含二维码图），否则 iframe/新窗口；
   - 官方 Native 适配器接入后展示 `code_url` 二维码；
4. 轮询到 `paid` → toast 成功 + 刷新钱包余额；
5. 充值记录：扩展 `components/TopupTable.tsx` 或新增"充值订单" Tab（单号/通道/金额/状态/时间）。

**管理端**

- `/admin/settings/billing`（计费与支付分区，两个 Tab）：
  - **通道配置**：易支付参数（pay_address/epay_id/epay_key）、min/max、预设档位、支付合规确认；
  - **支付订单**：筛选（单号/用户/状态）+ 表格 + 手工补单按钮
    （confirm dialog → `POST /admin/payment/orders/{id}/complete` → invalidate）。

## 7. 风险与合规

| 风险 | 说明 | 缓解 |
|---|---|---|
| 易支付合规性 | 个人/第三方收款通道，公司商用有合规风险 | 仅作 M0 快速通道；商户资质到位后切官方；前端加支付合规确认 |
| 回调丢失 | 网关已扣款但回调未达 | 管理端手工补单 + 订单状态可查询 + 定期对账任务核对 |
| 金额安全 | 回调金额篡改、重复入账 | MD5/RSA2 验签 + 服务端金额比对 + 幂等唯一约束 |
| 渠道同步误操作 | 自动建模型产生不可解释账单 | 默认预览确认；自动创建仅建定价 0 模型 |
| 上游模型变动 | 上游下线/改名导致路由失败 | 同步只停用不删除；渠道测试可随时验证 |
